# 📦 Token 优化实战存档（2026-09）

> **30 秒看懂**：本 vault 每次新对话的固定成本，从最初 **≈67,500 tokens** 压到 **≈18,500 tokens（-72%）**。核心不是"删规则"，而是：① 消除双文件重复 ② 红线蒸馏常驻 + 低频下沉 ③ 给巨型方法库加"按需跳转导航" ④ 用 Hooks 自动维护导航行号。规则一条没丢，全部可回滚。

---

## 一、优化前诊断（2026-08-27 实测）

| 常驻加载项 | 大小 | 估算 tokens | 问题 |
|---|:---:|:---:|---|
| 根 `CLAUDE.md` | 8.4 KB | ≈10,100 | 与 .claude 版大量重复 |
| `.claude/CLAUDE.md` | 45.3 KB | ≈55,300 | "精简"时藏起来的完整版，**仍每次全读**，等于没省 |
| 根 `AGENTS.md` | 2.1 KB | ≈2,000 | 内容是本库无关的 jCodeMunch-MCP 代码导航策略（疑似串台） |
| **合计** | 55.8 KB | **≈67,500** | 两份 CLAUDE 规则重复 1~7 次（医疗合规/查重/朋友圈/业绩突破等） |

**根因**：上次"798→150行"的优化把完整版移到了 `.claude/CLAUDE.md`，但 Claude Code **同样每次全读它**——固定成本几乎没降，指南声称的"-85%"实际只约 **-25%**。

---

## 二、执行步骤与量化收益

### 第 1 步：单轨合并（2026-09-05）— 效果最大

| 动作 | 结果 |
|---|---|
| 两份 CLAUDE.md 合并为一份精简根 `CLAUDE.md` | 规则两套合一，重复段落去重 |
| `.claude/CLAUDE.md` 降为 3 行指针（指向根文件） | 退出每次全读链 |
| 红线类规则（术语/查重/医疗合规/违规解密）**蒸馏常驻** | 不丢规则 |
| 低频细节（交付格式模板/进度条配置等）压缩为指针或内联 | 见第 3 步 |

**量化：67,500 → ≈21,900 tokens/会话（-67%）**

### 第 2 步：清场 — AGENTS.md + settings.json（2026-09-05）

| 文件 | 处理 | 量化 |
|---|---|---|
| 根 `AGENTS.md` | 备份后移出根目录（内容与本库无关） | 省 ≈2,000/会话 + 消除误导 |
| `.claude/settings.json` | 97 条 allow（55 条旧 Mac 路径 + 36 条调试命令）→ **7 条**；mcpServers 路径改 Windows | 68 KB → **547 B（-99%）**；启动/权限噪音大降 |

### 第 3 步：CLAUDE.md 两轮压缩（2026-09-05）— 增量有限

| 轮次 | 动作 | 量化 |
|---|---|---|
| A 展示块压缩 | 交付格式/快速导航/进度条配置表：31+15+16 行 → 压缩 | 21.9K → 20.7K（**只省 ~1K**） |
| 激进档 | 头部/知识加工框图/自动化总表 4 条超长行/质检链 15→12 条（合并同类项）/飞书录音/朋友圈/打包 | 20.7K → **18.5K** |

> **教训（重要）**：这两轮按"行数"预估能省 5~8K，实际只省 ~2K。因为 **markdown 壳（表格线/分隔线/空行）几乎不烧 token，真正烧 token 的是中文字符**。衡量压缩收益要看"中文字符/估算 tokens"，不是行数。

### 第 4 步：发现真正的 token 黑洞 — 巨型方法库（2026-09-06）

写安利脚本时 AI 会打开 [[脚本风格系统]]，实测它 **82KB ≈ 102,000 tokens**，是 CLAUDE.md 的 5 倍。同类的还有：

| 方法库文件 | 大小 | 估算 tokens |
|---|:---:|:---:|
| 脚本风格系统 | 82 KB | ≈102,000 |
| 公众号写作规则系统 | 19 KB | ≈23,000 |
| 视频号风险检测清单 | 15 KB | ≈18,600 |
| 张医生个人味道库 | 12 KB | ≈14,400 |
| 业绩突破导航 | 13 KB | ≈15,100 |

**关键认知反转**：现有 CLAUDE.md 本质是这些巨文件的"蒸馏层/免读缓存"——它让 AI **不用读 102K 原文**就能正确写脚本。若把 CLAUDE.md 改成纯路由表（"触发→去读脚本风格系统"），等于拆掉缓存、逼 AI 每次回源读 102K，单任务 token 反而 **6 倍暴涨**。**全量路由表化 = 负优化，不可行。**

### 第 5 步：给脚本风格系统加"🧭 本文件导航"（2026-09-06）— 结构性省 token

在文件顶部加导航块：声明"82KB/1100+行，勿通读"，必读区（已验证爆款公式 + 八步行55）+ 按需查表（选题→行152、开头→行570、铁律→行413……）+ 参考区明示跳过。**让 AI 用 Read(offset) 只读所需段落，不从头扫到尾。**

### 第 6 步：Hooks 自动维护导航行号（2026-09-06）

行号会随编辑漂移 → 配置 **PostToolUse hook**，每次我 Edit/Write 该文件后自动重算导航行号并回写：
- `.claude/scripts/sync-nav.js`（node 脚本，含 15 个锚点，优先取 H2 主章节避免被 H3 交叉引用抢占）
- `.claude/settings.json` 新增 `hooks.PostToolUse`（matcher: `Write|Edit`）
- **已验证全链路**：插入测试行 → 导航 1103→1105 自动更新；删除 → 自动回弹 1103。并修复了"真实感写作法"锚点歧义 bug。

> 局限：仅在我用工具编辑时触发；若在 Obsidian 手动编辑，需手动跑一次 `node .claude/scripts/sync-nav.js`。

## 四、可复用的方法论（转给团队/其他库）

1. **先诊断"每次必读"清单**：Claude Code 会全读 根 CLAUDE.md / .claude/CLAUDE.md / AGENTS.md。先列出所有常驻文件，再谈优化。
2. **衡量用中文字符，别用行数**：tokens 主要 = 中文字符 × ~1.5。表格线/空行/分隔符几乎不烧 token。估 tok ≈ 中文字 × 1.5 + 英文词 × 1.3。
3. **CLAUDE.md = 蒸馏层，不是路由表**：别把 CLAUDE.md 删成"触发→读某文件"。若目标文件是巨无霸，路由=负优化。正确做法是反向：给巨文件加"按需跳转导航"，让它可被局部读取。
4. **红线规则必须常驻**：医疗合规/查重/违禁词这类"每条必过"的判断规则下沉 = 漏检风险。宁可多烧几千 tokens 常驻。
5. **下沉前验证目标非空**：本次发现 `章节进度条-overlay.md` 是 0 字节空文件——下沉=丢规则。指针指向的文件必须真实存在且有内容。
6. **自动化靠 Hooks，不靠记忆**：重复性"编辑后同步"用 PostToolUse hook 脚本，别指望模型"记得"。脚本要幂等 + 静默失败 + 超时保护。
7. **动核心方法库前先备份**：所有改动前 `cp` 到 `.claude/backup/`，可随时回滚。

## 六、团队成员可直接复用的提示词

> **用法**：把下方对应段落的文字**整段复制**发给你的 AI 助手（Claude / ChatGPT / Kimi / 豆包 等均可，标注"Claude Code 专用"的需在用 Claude Code 的项目里发）。**动手前先备份**你的指令文件。
>
> **速选**：只用 ChatGPT 类对话工具 → **A + E**；用 Claude Code → **A + B + C + D + E**；C/D 仅当你有"超大方法库文件"时才需要。

### 提示词 A：通用 · 一条指令帮你优化"每次必读"的指令文件

```text
请帮我优化我的 AI 指令文件（如 CLAUDE.md / AGENTS.md / 系统提示词），目标是省 tokens。

【背景】这类文件每次新对话都会被完整读取，文件越大每次对话成本越高。实测中文最烧 token（约 1 汉字 ≈ 1.5 token），表格线/空行/分隔符几乎不烧。
【目标】在不丢失任何规则/能力的前提下尽量压缩。衡量标准用"估算 tokens"（中文字 × 1.5 + 英文词 × 1.3），不要只看行数。
【方法】
1. 先备份原文件（如 xxx.bak.日期）
2. 逐段扫描：
   ① 与系统自动注入重复的内容（技能列表等）→ 删或留一行指针
   ② 同一规则多处重复 → 只留一处
   ③ 大表格/清单（>5 行）→ 移到专项文档，原处留一行指针（指针指向的文件必须真实存在且有内容，否则=丢规则）
   ④ 版本历史/过程说明（"v1.2 新增了…"）→ 删除说明，规则本体保留
   ⑤ 互相重叠的准则 → 合并同类项
   ⑥ 大段示例/样例 → 保留链接不内联
3. 红线类规则（合规/安全/强制流程/违禁词）必须保留常驻，可压缩表述但绝不删除或下沉
4. 完成后输出对比报告：估算 tokens 前后 + 行数前后 + 修改清单
【红线】不删任何独有规则；指针指向的文件必须真实存在；红线规则保留原义
```

### 提示词 B：Claude Code 专用 · 先诊断"每次会话固定成本"

```text
请诊断我这个项目每次新对话的固定 token 成本（只分析、不改动）：
1. 找出所有会被自动加载的文件：根目录 CLAUDE.md、.claude/CLAUDE.md、AGENTS.md、子目录 CLAUDE.md
2. 逐个估算：中文字符数 / 行数 / 估算 tokens（中文×1.5 + 英文词×1.3）
3. 检查重复：同一规则（如"查重""合规""打包"）是否在多个文件各写了一遍
4. 检查 .claude/settings.json 是否塞了大量失效的 allow 路径、旧电脑路径、大段脚本
5. 输出一张表：文件 | 大小 | 估算 tokens | 冗余点；并标出"最值得优化的前三名"
```

### 提示词 C：Claude Code 专用 · 给"超大方法库文件"加导航（省最多）

```text
我有一个方法库文件，约 [XX]KB，每次干活时会被打开，AI 容易整篇读入浪费 tokens。
请在它顶部（标题下方）加一个「🧭 本文件导航」块：
1. 先声明"本文件较大，勿通读全文，按行号跳转"
2. 列出"每次必读"的核心段落（主流程），标注真实行号
3. 按"卡在哪步 → 去读哪节"列查表，每个关键小节标注真实行号
4. 把"参考/案例/历史"类非必需段落列为"跳过区"
5. 锚点匹配：若某关键词出现多次，选标题层级最低的那个（H2 > H3，即主章节优先，
   不要被"### 交叉引用/详见[[#某章]]"这类子标题抢走）
完成后把导航块给我确认，确认前不要改其它内容。
```

### 提示词 D：Claude Code 专用 · 给导航行号配"自动同步 Hook"

```text
我给文件 [文件名] 加了"标题→行号"导航，行号会随编辑漂移。
请帮我配置一个 PostToolUse hook（写进 .claude/settings.json）来自动同步：
1. 写一个 node 脚本，每次我用 Edit/Write 修改 [文件名] 后自动触发
2. 脚本逻辑：读 stdin 的 hook JSON → 判断被改文件是不是 [文件名] → 是则重算导航各锚点标题的真实行号并回写；不是则静默退出
3. 锚点匹配：优先选标题层级最低（H2>H3>H4）的主章节，避免子标题抢主章节
4. 替换导航时保持总行数不变（避免替换本身又造成位移），最多迭代 3 轮收敛
5. 要求：幂等、失败静默、加 timeout（约 15 秒）
完成后请做两步验证给我看：① 管道测试（模拟 stdin）② 真实触发测试（故意插入一行，
确认导航 +1，再还原确认回弹）
```

### 提示词 E：优化后 · 自检"规则有没有丢"

```text
请帮我核对 [优化后文件] 相对备份 [原文件]，确认没有丢规则：
1. 列出原文件里所有含"强制/必须/红线/不可/禁止/一律/不得"的句子
2. 逐个确认它们在优化后文件里仍能找到（允许换表述，含义必须保留）
3. 特别检查被"下沉"的规则——指针指向的文件是否真实存在、内容是否覆盖
4. 输出清单：每条红线 → 存在 ✓ / 丢失 ✗
```
