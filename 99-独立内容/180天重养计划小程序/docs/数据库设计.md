# 📦 数据库设计 — 180天重养计划

> 3 个集合，权限全部选 **「仅创建者可读写」**（所有读写走云函数，锁死最安全）。

---

## 集合 1：`plans`（计划，一个社区一份）

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 系统自动生成 |
| `name` | string | 计划名称，如「2026 秋季重养计划」 |
| `inviteCode` | string | 6 位邀请码（去易混字符 0/O/1/I，仅大写） |
| `startDate` | string | 开始日期 YYYY-MM-DD |
| `totalDays` | number | 固定 180 |
| `phaseCount` | number | 固定 6 |
| `daysPerPhase` | number | 固定 30 |
| `ownerOpenid` | string | 发起人 openid |
| `ownerNickname` | string | 发起人昵称（改昵称时同步更新） |
| `createdAt` | number | 创建时间戳 |

## 集合 2：`members`（成员，一人一条，带冗余聚合字段）

> 工作台效率关键：排行榜 / 日历格 / 完成率全部直接读冗余字段，不用实时聚合。

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 系统自动生成 |
| `planId` | string | 所属计划 |
| `openid` | string | 成员 openid |
| `nickname` | string | 昵称（1-12 字） |
| `joinedAt` | number | 加入时间戳 |
| `dayStatus` | array\<number\> | 长度 180，`idx = dayNo-1`；值：`0` 无 / `1` 仅早 / `2` 仅晚 / `3` 早晚都有 |
| `currentStreak` | number | 当前连续天数（宽容口径：当天任一时段打卡即算当天有） |
| `bestStreak` | number | 历史最佳连续 |
| `totalDays` | number | 有打卡的天数 |
| `fullDays` | number | 早晚都完成的天数（严格口径，算完成率用） |
| `lastCheckinDate` | string | 最近打卡日期 YYYY-MM-DD |
| `updatedAt` | number | 更新时间戳 |

## 集合 3：`checkins`（打卡明细，存照片 fileID）

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | **确定性主键**：`${planId}_${openid}_${date}`（一天一人一条，天然去重） |
| `planId` | string | 所属计划 |
| `openid` | string | 打卡人 |
| `date` | string | 打卡日期 YYYY-MM-DD |
| `dayNo` | number | 第几天 |
| `morning` | object \| null | `{photo: fileID, text, time}`，未打卡为 null |
| `evening` | object \| null | 同上 |
| `createdAt` | number | 创建时间戳 |
| `updatedAt` | number | 更新时间戳（今日动态按此倒序） |

## 索引建议（云开发控制台 → 数据库 → 对应集合 → 索引管理）

| 集合 | 索引字段 | 用途 |
|------|---------|------|
| `plans` | `inviteCode` | 加入校验（查码） |
| `plans` | `createdAt` | getPlan 取最近计划（未加入时） |
| `members` | `planId` + `currentStreak` | 排行榜倒序 |
| `members` | `planId` + `openid` | 幂等加入 / 打卡校验 |
| `members` | `openid` | 找我的计划（getPlan） |
| `checkins` | `planId` + `date` + `updatedAt` | 今日动态 feed |
| `checkins` | `planId` + `openid` + `date` | 我的打卡明细（getMyCheckins） |

> 成员 ≤50 人、打卡 ≤2 万条以内，单集合完全没问题。建议索引先全建上，避免查询报「缺少索引」。

## 权限设置

**三个集合都选「仅创建者可读写」（最严），所有读写都走云函数。**

原因：云函数拥有管理员权限，不受客户端数据库权限限制。前端页面从不直接读写数据库（见 `miniprogram/utils/api.js` 全部走 `wx.cloud.callFunction`），所以把数据库权限锁死最安全。

## 照片云存储权限

- 上传：前端 `wx.cloud.uploadFile`（路径 `checkins/{planId}/{date}_{slot}_{timestamp}.jpg`）
- 权限：**「仅创建者可读写」即可**（免费套餐的默认项，无需升级）
- 共享加载：`getDashboard` 云函数对今日动态里的照片统一调用 `cloud.getTempFileURL` 转成临时链接，`<image src="https://...">` 渲染别人照片；「我的」页只显示自己的照片，直接 `<image src="cloud://fileID">`（创建者可读自己的文件）
- 照片属于用户隐私，只对加入计划的伙伴可见（需邀请码才能进计划）

## 核心算法备忘

- **streak（宽容）**：`calcStreak` 从今天（或最近打卡日）往前数连续天，当天任一时段打卡即算当天有 → 排行榜
- **completionRate（严格）**：`全员 fullDays 总数 ÷ (成员数 × 已过天数)`，按每 30 天分段算阶段趋势
- **去重三重防线**：确定性 `_id` + slot 已存在拒绝 + `add` 重复键异常兜底；允许「先晚后早」（slot 独立）
- **日期**：客户端传本地日期分桶；服务器用北京时间 `Date.now()+8h` 算"今天"；天数差用 `Date.UTC` 求差避免时区坑
