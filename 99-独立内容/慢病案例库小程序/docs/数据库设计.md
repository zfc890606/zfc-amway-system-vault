# 📦 数据库设计 — 慢病案例库

## 集合：`cases`

| 字段 | 类型 | 说明 |
|------|------|------|
| `_id` | string | 系统自动生成 |
| `title` | string | 醒目标题（AI 生成可改），如「痛风·男42岁·尿酸620→380·3个月复盘」 |
| `category` | string | 板块：肥胖/痛风/糖尿病/高血压/免疫/症状管理/其他 |
| `alias` | string | 客户化名（脱敏，不存全名） |
| `ageRange` | string | 年龄段，如「40-50岁」 |
| `chiefComplaint` | string | 主诉 / 背景 |
| `metrics` | string | 检查指标变化，如「尿酸 620→380；体重 85→72kg」 |
| `plan` | string | 调理方案（饮食/运动/营养素/生活方式） |
| `result` | string | 结果复盘（效果、反馈、可复制经验） |
| `tags` | array\<string\> | 关键词标签 |
| `openid` | string | 录入人 openid（用于统计"我录入的"） |
| `deleted` | boolean | 软删除标记 |
| `createdAt` | number | 创建时间戳 |
| `updatedAt` | number | 更新时间戳（列表按此倒序） |

## 索引建议（云开发控制台 → 数据库 → cases → 索引管理）

| 索引字段 | 用途 |
|---------|------|
| `deleted` + `category` + `updatedAt` | 首页板块 Tab 列表 |
| `deleted` + `updatedAt` | 全部列表 |
| `openid` + `deleted` | "我录入的"统计 |

> 高频查询字段建议加索引；案例数在 10 万条以内单集合没问题。

## 权限设置

**建议：数据库权限选「仅创建者可读写」（最严），所有读写都走云函数。**

原因：云函数拥有管理员权限，不受客户端数据库权限限制。前端页面从不直接读写数据库（见 `utils/api.js` 全部走 `wx.cloud.callFunction`），所以把数据库权限锁死最安全。

## 字段设计原则

1. **脱敏优先**：只存化名/年龄段，健康信息属敏感个人信息（《个人信息保护法》），不存可识别身份的信息
2. **文本为主**：V1 全部用文本字段，图片（体检报告/舌象）V2 再加云存储
3. **板块可扩展**：板块列表在 `miniprogram/utils/categories.js` 定义，改一处全端同步；数据库存的是 `category` 字符串，兼容旧数据
