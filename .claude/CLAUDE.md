## 0b. 视频号医疗合规质检 — 所有脚本强制过检

**2026-08-09 生效令：** 视频号判定医疗/大健康账号"疑似引导线上/线下问诊、医疗教学"导致限流、账号受限。从今以后**写脚本必须过医疗合规三条红线，不过不交付**：

0. **账号级前提（医疗/健康账号）**：账号必须先完成视频号职业认证（无资质科普 = 账号级风险）；认证要求 → [[视频号风险检测清单]]「〇·1 资质认证」
1. **不引导问诊**："评论区告诉我，我帮你分析/看看"、"把你的情况/体检报告发我"、"私信我帮你调理" → 一律删，改纯认知互动（"这条说的情况你遇到过吗？评论区聊聊看法"）
2. **不引导评论区公开讨论病情**："你什么病/指标？评论区说说" → 改成"聊聊你的看法"
3. **不引导平台外学医/领医疗资料/收徒**："加微信领资料、教你调理、中医收徒" → 删；医疗内容不挂"领资料"钩子
4. **全账号不留联系信息**：头像/签名/简介/公众号名/标题/定位/活动/直播预约/评论/音频/合集
5. **营养健康类结尾强制加免责**："以上为健康科普分享，不构成诊疗建议，个体情况请咨询专业医师"

详细细则 → [[视频号风险检测清单]]「〇、医疗问诊合规」；写稿规则 → [[脚本风格系统]] 铁律15

## 1. Think Before Coding — 先想再写

**不要假设。不要隐藏疑惑。摆出权衡。**

实施前：
- 明确陈述你的假设。如果不确定，就问。
- 如果存在多种解读，都列出来——不要偷偷选一个。
- 如果有更简单的方案，说出来。必要时坚持。
- 如果不清楚，停下来。说出哪里困惑。提问。

## 2. Simplicity First — 简单第一

**用最少的代码解决问题。不要加没被要求的东西。**

- 不加超出要求的功能
- 不为一次性使用做抽象
- 不加没被要求的"灵活性"或"可配置性"
- 不为不可能的场景写错误处理
- 如果写了200行但50行能搞定，重写

问自己："资深工程师会觉得这过于复杂吗？"如果是，简化。

## 3. Surgical Changes — 外科手术式改动

**只动必须动的。只清理自己造成的混乱。**

编辑现有文件时：
- 不要"顺手改进"旁边的代码、注释或格式
- 不要重构没坏的东西
- 匹配现有风格，即使你自己会做不同的选择
- 如果看到无关的死代码，提一句——不要删

当你的改动产生了孤儿：
- 删除你的改动导致不再被引用的 import/变量/函数
- 不要删除预先存在的死代码，除非被要求

检验标准：每一行改动的代码都应当能直接追溯到用户的请求。

## 4. Goal-Driven Execution — 目标驱动执行

**定义成功标准。循环直到通过验证。**

把任务转化为可验证的目标：
- "加验证" → "先为无效输入写测试，然后让它们通过"
- "修这个 bug" → "先写一个能复现它的测试，然后让测试通过"
- "重构 X" → "确保重构前后测试都通过"

多步任务要陈述简要计划：
```
1. [步骤] → 验证：[检查项]
2. [步骤] → 验证：[检查项]
3. [步骤] → 验证：[检查项]
```
