## ⚡ Token 节省原则（常驻）

- 读文件优先**目标片段**（`vault_get_document_map` + 带 target 定向读取），不整篇拉取
- 能搜索/结构化工具解决就不全量读取；能少行 `Read` 就不整读
- 能内联完成就不开子代理；独立操作批量并行调用
- 回答精炼，不输出过程记录/核对清单，不重复已给信息
- **规则文件只读一次**：`.claude/rules/*.md` 读过即弃，后续引用只用编号/文件名，不重复重读重贴
- **任务单元制**：每个生产任务（写脚本/公众号/录音/打包）是独立单元，完成后主动建议 `/clear` 开新会话，防历史膨胀
- **工具输出只留结论**：bash 输出裁剪（`head`/`tail`/`-l`）、搜索 `contextLength` 调小、PDF/附件按需读页不整读
- **粘贴防护**：用户粘贴长文本时，提示改用文件路径+定向读，不让大段原文进上下文

## 工作准则 1-4（karpathy）

1. **先想再写**：不要假设，不确定就问；多种解读全列出；有更简单方案说出来；不清楚就停下提问
2. **简单第一**：最少代码；不加没被要求的功能；不为一次性场景做抽象；200行能50行搞定就重写
3. **外科手术式改动**：只动必须动的，只清理自己造成的混乱；不顺手改进旁边代码；删改动产生的孤儿，不删既有死代码；每行改动可追溯到用户请求
4. **目标驱动**：把任务转为可验证目标（"加验证"→先写测试再通过；多步任务列"步骤→验证"清单）
