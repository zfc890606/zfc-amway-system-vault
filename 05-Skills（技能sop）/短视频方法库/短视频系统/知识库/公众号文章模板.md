# 📱 公众号文章模板

> 类比 [[知识库/05-Skills（技能sop）/短视频方法库/短视频系统/知识库/脚本模板|脚本模板]]，专门为 WeChat 公众号排版设计。
> ⚠️ **写之前必读 [[公众号写作规则系统]]**（张医生专属写作SOP：双阶段策略+选题/标题/开头/结构/合规）→ 再到本文套结构排版。
> 表达方式从口播体切换为阅读体。

---

## 📄 文件结构规范（发布区标记 · 2026-08-11）

每篇公众号文章文件统一用发布区标记，**推送草稿箱时只提取发布区**（内部记录一律不推）：

```markdown
---
frontmatter（内部记录：title/created/status/source_script 等）
---

<!-- PUBLISH:START -->

# 标题
（正文 + 📚 参考资料 + 免责声明）

<!-- PUBLISH:END -->

## 📱 朋友圈转发文案（内部记录 · 不推送）
## 🎯 本期测试变量（内部记录 · 不推送）
```

> ⚠️ `publish` 前必须先提取 `<!-- PUBLISH:START -->`…`<!-- PUBLISH:END -->` 区间内容到临时文件，再推草稿箱（否则 frontmatter/朋友圈文案/测试变量会被当正文发出去——article-101 教训）。

## 🚀 交付格式（2026-08-11 生效令 · 纯净版）

**写公众号 = 只交付纯净版**，可直接复制发布。其他内部记录默认不展示：

```
【公众号文章 · 纯净版】

标题：XXXX

（正文：含 H2 分段 + 金句引用 + 📚 参考资料 + 免责声明，可直接复制）

---
（已同步推送到草稿箱 · 纯净版）
```

- ✅ **给**：标题（1个已定/3个备选按需）+ 正文（纯净版，含参考资料+免责声明）
- ❌ **默认不给**：frontmatter、朋友圈文案、🎯测试变量、文献锚点、进度条等内部记录（都留在文件内部区）
- 用户需要朋友圈文案/完整文献时，再单独说"给我朋友圈文案/文献清单"
- 推送动作照旧：写完默认直接推草稿箱（2026-08-11 生效令）

## 短视频脚本 → 公众号文章 转化要点

| 短视频脚本 | 公众号文章 |
|-----------|-----------|
| 无标题 | H1 `# 标题` — 吸引点击，15-20字 |
| 靠情绪曲线推进 | H2/H3 分段 `##`/`###` — 逻辑清晰可扫读 |
| 口语重音 | `> 引用` 突出金句 — 读者视线落脚点 |
| 语气强调 | `**加粗**` 强调核心观点 |
| "第一第二第三"口述 | `-`/`1.` 列表 — 结构化呈现 |
| 短句（口语体） | 较长段落但不过密（每段3-5行为宜） |
| 结尾一句话 | 结尾 CTA 段落 — 引导关注/评论/转发 |
| 纯口播 | 可配封面图+导语（文章摘要） |

## 通用结构模板

### 标题（H1）

> 15-20 字，含关键词 + 好奇心/利益点
> 例：*做安利第一步就搞反了？90%的新手都栽在这*

### 导读（可选，斜体）

> 2-3 句引出痛点或问题，让读者产生"说的就是我"的代入感
> *你是不是也觉得做安利就是不停卖产品？我告诉你，真正做起来的人，根本不是这么干的。*

---

### 正文分段

```
## 第一段：痛点/场景切入（H2）
  延续标题的钩子，3-5句把读者的处境说透。
  用「你」开头，保持对话感。

## 第二段：核心方法/观点（H2）
  展开 2-3 个要点，每点用 H3 或列表：
  
  ### 要点一：XXXX
  展开说明，可以用 **加粗** 强调关键词。
  > 金句引用 — 读者扫读时视线落在这

  ### 要点二：XXXX
  同上结构。

## 第三段：底层逻辑/原因（H2）
  为什么这个方法有效？给他一个认知框架。
  不用太长，3-4句讲透即可。

## 结尾：总结 + CTA（H2）
  一句话总结全文核心。
  
  > 金句收束
  
  💬 你卡在哪一步？评论区告诉我。
  📌 觉得有用点个「在看」，转发给需要的朋友。
```

## 排版规范

| 元素 | 使用场景 | 格式 |
|------|---------|------|
| `#` H1 | 标题（全文唯一） | `# 标题文字` |
| `##` H2 | 主要段落开头 | `## 段落标题` |
| `###` H3 | 子要点 | `### 子标题` |
| `> 引用` | 金句/重点结论 | `> 金句内容` |
| `**加粗**` | 关键术语/核心观点 | `**关键词**` |
| `-` 列表 | 并列要点 | `- 第一点` |
| `1.` 列表 | 有序步骤 | `1. 第一步` |
| `---` 分隔线 | 大段落切换 | `---` |
| `💬`/`📌` emoji | 结尾 CTA 点缀 | 适量使用 |

### 段落长度控制

- 每段 **3-5 行**为宜，不超过 7 行
- 重要观点单句成段 = 视觉强调
- 段落间空行 — 移动端阅读需要呼吸感

## 两种创作路径

### 路径 A：脚本→文章（WeWrite 管线 — 推荐）

```
你说"把脚本003改成公众号，推到草稿箱"
  → 读脚本 + 匹配知识卡片/洞见卡
  → Phase 1：WeWrite 写作引擎
     ├─ brief.yaml（任务书：受众/问题/核心判断/反方）
     ├─ claims.yaml（主张清单：3-6条）
     ├─ draft.md → wewrite-review（5项编辑评分）
     └─ run finish（封存至历史）
  → Phase 2：Vault 质检三道关
     ├─ humanizer-zh 去AI味
     ├─ content-risk-detector 内容风险检测
     └─ ai-detector AI痕迹复核
  → Phase 3：publish.py 样式发布（bold-navy 主题）
     ├─ H1/H2 → #1e3a5f 深蓝
     ├─ 加粗 → #1e3a5f 深蓝
     ├─ 引用块 → 浅蓝底 + 中蓝字
     └─ API上传 → 公众号草稿箱 ✅
  → 你只需去 mp.weixin.qq.com → 加封面图 → 发布
```

### 路径 B：独立创作（从零写）

```
你说"写一篇公众号文章，主题是XXX"
  → 读取痛点排行榜 + 关键词库 + 金句素材库 + 知识卡片
  → 按公众号结构创作（H1标题→导读→H2/H3分段→金句引用→CTA结尾）
  → 质检：humanizer-zh → risk-detector → ai-detector
  → 存 公众号草稿/article-XXX-标题.md
```
