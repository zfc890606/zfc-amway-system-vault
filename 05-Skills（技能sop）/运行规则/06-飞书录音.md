# 06 · 飞书录音 & 朋友圈同步

## 飞书录音处理标准流程

自动模式（2026-09-03 起）：飞书新妙记每 15 分钟自动同步进 `日记（飞书笔记存档）/` 并标记 `status: 待处理`；随后 **launchd 自动队列**（`com.vault.feishu-process`，每 60 秒，仅 Obsidian 运行时）把每条待处理笔记交给 **Claude Code 无人值守**（`claude -p`）跑完整知识加工，无需用户开口。仍可用 **"帮我拉一下飞书的录音"** 手动补跑。

自动处理会完成：
- 判断所属板块（AI/创业/营养/团队/成长/认知/视频/生活）
- 精读转写 → 提炼金句/洞察 → 创建洞见卡（DJ-*）→ `00-灵感库（标记灵感）/洞见卡/`；主题够深 → 知识卡片（KC-*）→ `00-灵感库（标记灵感）/知识卡片/`
- 创业/认知/团队/成长/生活/AI/视频运营类 → 同步生成朋友圈文案（PYQ-*）→ `00-灵感库（标记灵感）/朋友圈文案库/` → 自动同步飞书（**营养科普类不配 PYQ**）
- 适合短视频 → 更新 [[00-灵感库（标记灵感）/安利选题库.md|安利选题库]]（必先查重：重复只累加频率/标注来源，不重复建条目）
- 全部完成 → 该笔记状态 `status: 待处理` → `status: 已处理-自动`（被查重铁律判为完全重复 → `已处理-跳过重复`）

##### 重要规则
- **🔒 锁死（2026-08-18）**：飞书录音同步落点强制 = `日记（飞书笔记存档）/`。同步脚本 `~/.scripts/feishu-sync/feishu-to-obsidian.py` 的 `Config.vault_path` 已加护栏：配置被改成其他路径（尤其 `日记（每日日记）`）会自动告警并纠正回飞书笔记存档。**禁止使用 `日记（每日日记）`**；config 文件：`~/.config/feishu-obsidian/config.json`。
- **不问用户**：拉录音后直接跑完整流程（洞见卡/知识卡片/朋友圈文案/选题更新全部自动，含朋友圈同步飞书），不需要问任何确认
- **自动队列（2026-09-03 起）**：执行体 = `claude -p` 无人值守，包装器 `~/.scripts/feishu-sync/feishu-auto-process.sh`（launchd `com.vault.feishu-process` 每 60s 调用，仅 Obsidian 在跑时处理；单实例锁防重入）。headless 与手动会话同源，产出质量 = 手动 Claude 水平
- 单条失败不中断其余；无待处理笔记时零成本空转。日志：`/tmp/feishu-auto.stdout.log`（产出）· `/tmp/feishu-auto.stderr.log`（运行）

## 📱 朋友圈文案 → 飞书自动同步

每次产出朋友圈文案卡（`PYQ-*`，无论来自知识加工还是飞书录音流程），**默认自动同步到飞书知识库「朋友圈文案库」**，不问用户：

```bash
python3 "/Users/mac/Documents/zfc最强大脑/99-独立内容/飞书文案库同步/sync_pyq_to_feishu.py"
```

- 工具目录：`99-独立内容/飞书文案库同步/`（复用「录音同步」应用，凭据自动读取）· 新卡自动建文档，改过的卡覆盖更新
- 同步失败时：提示跑 `reauthorize.py` 重新授权 · 说明文档：[[99-独立内容/飞书文案库同步/接入指引.md]]
