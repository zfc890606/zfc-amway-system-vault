# 《飞书CLI + Claude Code：AI自动化协作系统》

> **一句话本质**：
> 飞书CLI是AI agent的企业协作接口——它让AI从"只能读写本地Markdown文件"进化到"能在飞书平台自动创建文档、推送资讯、生成数据面板和画板"，彻底解决了本地知识库在线分享和自动投送的最后一公里问题。

---

## 🧩 因果 / 原理

**它解决了什么问题？**

用 Obsidian + Claude Code 搭知识库的创业者普遍卡在一个问题上：

> **本地做得再好，出不去。**

具体表现为：
- 手机上几乎没法查看本地 Markdown 文档
- 分享给朋友或粉丝需要发文件，不能一条链接搞定
- 团队协作困难——知识库在个人的 Obsidian 里，别人看不了
- AI 产出的报告、分析、图表全部困在 .md 里，无法在线展示

**为什么飞书CLI能解决？**

飞书CLI（Feishu CLI）不是聊天机器人，它是**一套给AI agent调用的命令行工具集合**。可以把它理解为"飞书的使用说明书+操作权限"——AI拿到它之后，知道了飞书有什么能力、怎么用、并且有了操作权限。

核心突破在于**能力边界的扩展**：

| 维度 | 之前（纯Obsidian） | 之后（Obsidian+飞书CLI） |
|:----|:-----------------|:----------------------|
| 存储 | 本地 Markdown | 云文档 + 本地双备份 |
| 查看 | 仅限电脑 | 手机/电脑/平板全端 |
| 分享 | 发文件/截屏 | 一条链接公开分享 |
| 协作 | 单人 | 团队可编辑/评论 |
| 格式 | 纯文本 | 文档+表格+画板+信息图 |
| 自动化 | Claude Code本地执行 | AI主动在飞书创建/投递 |

有了这个接口，AI的产出流程从：
```
你发指令 → AI在本地生成.md → 你看不到（除非打开电脑）
```
变成了：
```
你发指令 → AI调用飞书CLI → 在线文档/表格/画板 → 手机就能看 → 一条链接分享
```

## 🛠 可执行方法

### 最小行动（今天就能做）
把飞书CLI装进你的Claude Code：`[一行安装命令，约2分钟]` → 让AI在飞书云文档里创建一篇测试文档，体验"AI产出直接出现在在线协作平台"的感觉。

### 完整执行步骤

**第一步：安装飞书CLI并接入AI agent**
1. 获取飞书开发者凭证（App ID + App Secret）
2. 在Claude Code中执行安装命令
3. 配置API权限（文档、表格、消息、画板等）
4. 验证连接：让AI用飞书CLI创建一个测试文档

**第二步：搭建4大自动化管线**

| # | 管线 | 输入 | AI动作 | 飞书输出 |
|:-:|:----|:----|:-------|:--------|
| 1 | **调研报告** | 发一个竞品网址 | 爬取分析→按结构写成报告 | 飞书云文档，自动排版 |
| 2 | **每日资讯** | 设定关键词/来源 | 定时抓取→筛选→摘要 | 飞书消息推送（手机可看） |
| 3 | **月度总结** | 工作记录/周报 | 读取记录→分析→汇总 | 飞书文档+多维表格面板 |
| 4 | **数据面板** | 对接API（广告/店铺） | 拉取数据→可视化 | 飞书多维表格+图表视图 |

**第三步：利用飞书画板做可视化表达**
1. 让AI根据文档内容自动生成画板（思维导图/路线图/架构图）
2. 文档+画板的组合形式比纯文字更直观
3. 适合：文章逻辑梳理、产品路线图、知识体系可视化

**第四步：打通Obsidian→飞书迁移链路**
1. Obsidian的Markdown文件可直接上传到飞书云文档
2. 飞书支持Markdown格式的上传、编辑和下载
3. 一条链接即可公开分享
4. 实现"本地编辑→在线发布→多渠道分享"的完整闭环

## 📍 场景与边界

### 适用场景
- **一人公司（OPC）/ 小团队创业者** — 用AI+飞书替代多个工具，降低运营成本
- **已有Obsidian知识库但苦恼于分享问题的人** — 飞书CLI是最短路径
- **需要定时输出资讯/报告的内容创作者** — AI自动调研+推送
- **需要数据可视化的运营者** — AI对接API生成多维表格面板
- **团队协作场景** — AI作为"虚拟成员"自动产出文档到共享空间

### 边界条件
- **前提要求**：需要飞书企业版或开发者账号（个人版部分API受限）
- **学习曲线**：虽然安装只需2分钟，但配置API权限和理解飞书CLI命令需要一定技术基础
- **不适用于**：不使用飞书作为协作工具的个人或团队；对API/命令行完全零基础且无人协助的用户
- **常见失败原因**：
  - API权限配置不全（AI能创建文档但发不了消息）
  - 定时任务（每日资讯推送）没有配置好触发机制
  - 数据面板对接的API数据源不稳定
  - 飞书画板的功能边界不清晰（画板适合做图，不适合做复杂数据分析）
- **注意事项**：飞书CLI是开源工具，配置时注意API密钥安全
