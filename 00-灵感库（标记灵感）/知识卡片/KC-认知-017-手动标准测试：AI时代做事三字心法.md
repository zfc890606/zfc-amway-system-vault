# KC-认知-017 手动·标准·测试：AI时代做事三字心法

> **一句话本质**：用好AI不是学技术，而是先建立三个底层行为习惯——手动跑通最小闭环（产生"一"）、在做事中提炼标准（建立基准线）、用测试心态替代完美主义（持续迭代）。三者递进，缺一不可。

---

## 🧩 因果 / 原理

### 解决了什么问题？

大多数人用AI的三大困境：

| 困境 | 表现 | 根因 |
|------|------|------|
| 幻想AI创造 | 让AI从0到1做东西，结果给的是通用模板 | 跳过"手动"，自己没有"一" |
| 跟AI聊无止境 | 花几个小时什么都没沉淀，答案跟别人的一样 | 没有"标准"，对话不收敛 |
| 做不好就焦虑 | 越焦虑越做不好，陷入负循环 | 没有"测试"心态，追求一次性完美 |

这三个问题的根因：**跳过了"手动·标准·测试"的递进链条。**

### 为什么有效？

这三个词是一个完整的递进做事系统：

```
① 手动 ──────→ ② 标准 ──────→ ③ 测试
(从0到1)      (从1到基准)    (从基准到迭代)
    │              │               │
    ▼              ▼               ▼
先跑通最小    在做事中提炼     拆解要素
闭环，不    输入/输出/验    针对单项变量
追求完美    证三标准       预测→验证→调整
    │              │               │
    └──────────────┴───────────────┘
                    │
                    ▼
         AI不再给你通用答案
         而是基于你的"一"
         在你的标准线上
         帮你精准迭代
```

**三者的核心关系：**
- **没有手动** → 你没有"一"，AI放大的是0
- **没有标准** → 你跟AI的对话是散乱的，没有收敛方向
- **没有测试** → 你永远在焦虑"做不好"，而不是快乐地"测到什么"

### 与已有体系的共振

这个框架与你已深度内化的 Karpathy 四条准则高度契合：

| 手动·标准·测试 | Karpathy 准则 | 你的短视频创作版 | 你的业绩突破版 |
|--------------|--------------|----------------|--------------|
| **手动** | Simplicity First | 先手动跑通一条完整视频，再让AI优化环节 | 先亲自带一个部门走通流程，再复制方法论 |
| **标准** | Goal-Driven Execution | 脚本风格系统+选题自查+质检清单=你的标准体系 | S2/S3/S4不同带法+每周节奏=你的管理标准 |
| **测试** | Think Before Coding | 每条视频测一个变量，预测→数据→迭代 | 与部门试不同方法，看数据再调策略 |

但**"手动·标准·测试"更简洁、更好记、更适合向团队和伙伴传播**——6个字就能说清楚AI时代的做事心法。

## 🛠 可执行方法

### 第一步：手动——先跑通最小闭环

**最小行动**：今天选一件你一直想用AI做但还没做的事，先完全手动做一遍。不管多粗糙，跑通就算完成。

**短视频场景：**
- 手动写一条完整脚本（不依赖AI），从构思到成稿
- 手动剪一条视频，从素材到导出
- 手动发布并跟踪数据跑一圈

**安利场景：**
- 手动走一遍OPP的完整流程，自己讲一次
- 手动带一个伙伴走完"四确定法"的每一步
- 手动完成一次顾客跟进的全过程

### 第二步：标准——在做事中提炼基准线

**最小行动**：做完一件事后花5分钟问自己——"这次如果变成下次的标尺，我定什么标准？"

**AI三标准（和AI对话前必设）：**

> **输入标准：** 这次给AI的信息是什么格式？什么质量才算合格？
> **输出标准：** 我要AI产出什么格式？什么水平的输出算好？
> **验证标准：** 我怎么判断AI给的好不好？能不能说清楚"好"在哪？

**短视频场景：**
- 你的脚本风格系统+选题自查+质检清单=已建成的一套标准体系
- 每条视频的数据指标（2秒跳出率/5秒完播率/互动率）就是你的基准线
- 每次复盘问自己：数据达标了吗？标准需要调整吗？

**安利场景：**
- 业绩突破导航的S2/S3/S4不同带法就是你的管理标准
- 每周节奏（周一方向→周三进度→周五复盘→周日蓄能）就是你的执行基准线
- 不同部门不同带法，但不代表没标准——恰恰说明你有"因人而异"的标准

### 第三步：测试——用预测-验证循环迭代

**最小行动**：下次做任何事之前，先问"这次我主要测哪个变量？"只测一个，不贪多。

**短视频测试循环：**

```
① 选变量 → 这期测开头钩子
② 做预测 → "我猜2秒跳出率是35%以内"
③ 发出去 → 正常发布
④ 看数据 → 实际2秒跳出率是多少？
⑤ 分析差异 → 为什么预测和实际不一样？
⑥ 下次调 → 基于这个发现，下次调什么？
```

**安利场景：**
- 测试不同话术在OPP中的反馈（哪段最打动人？）
- 测试不同跟进方式（线上/线下/社群）哪个转化率更高
- 测试不同部门最适合的领导力风格（部门A用S3还是S4？）

## 📍 场景与边界

### 适用场景
- 学了AI工具但不知道怎么真正用到工作里的人
- 每天很忙但不知道沉淀了什么的人
- 做短视频一直不出成绩，开始怀疑自己的人
- 带团队但总觉得"自己的经验没法复制"的团队长

### 边界条件

| 原则 | 不是 | 是 |
|------|------|-----|
| 手动 | 永远手动不用AI | 手动是起点，跑通后一定用AI加速 |
| 标准 | 定死了就不改 | 随经验增长持续迭代升级 |
| 测试 | 随心所欲试 | 有明确变量、有预测、有数据验证的刻意练习 |

三者有递进关系，但也可以并行——你在手动跑通的同时可以开始提炼标准，在建立标准的同时可以用测试优化。
